# v0.83 777 涂装启动恢复

v0.82 的 DX11 与 DX12 初始化都要求读取 777 涂装，即使起飞前选择的机型是空客。旧资源目录只要少了 `b777.fctex`，图形初始化就会失败。v0.83 共用同一个加载流程，只把 `atlas.fctex` 当作图形初始化的必要贴图。

777 涂装缺失、无法打开、文件头错误、截断或尺寸不匹配时，777 的材质层改用完整的纯白 mip 链，让原顶点色和光照继续生效。浦东影像及其他材质层仍从基础图集加载。启动日志标注 `b777.fctex` 和具体原因。恢复正确文件并重启后恢复原涂装。基础图集失败仍向调用方报错，并标注 `atlas.fctex`。

Linux 回归使用真实发行涂装及临时测试图集，涵盖完好、缺失、损坏、截断、尺寸不符，以及恢复涂装。检查了其余材质层与原数据一致、基础图集失败时的诊断、替代层每级尺寸及像素。Windows CI 与目标机验收需分别记录。

Boot Camp 上使用发行资源启动 DX11，在副本中暂时移开 `assets/b777.fctex` 再启动。检查菜单和 A330 可用、777 外模显示中性颜色、`startup.log` 记录原因，随后还原涂装文件并重启对照。驱动支持 DX12 时重复检查。最后以 v0.82 和 v0.83 相同机位进行帧时对照，并完成一次滑行到着陆结算。
