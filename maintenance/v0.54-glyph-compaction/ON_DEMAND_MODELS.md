# v0.97 按需加载飞机网格

启动仅调用当前机型的模型加载；换机及读档先准备目标机型，再提交飞行状态。缺失或损坏的其他机型默认网格不再阻止当前机型启动。所选机型缺少必需默认网格且没有有效自定义模型时，启动仍报错；运行中的换机或读档会提示失败并保留原飞行，不保存失败的换机状态。

本次访问过的机型继续保留在进程内，程序生成机型也记录为已准备，避免每帧/重复选择探测磁盘。自定义优先、损坏自定义回退、导入、旋转和恢复默认沿用已有行为。缓存不设淘汰上限，访问全部机型后的网格内存可能回到旧版水平。首次换机仍同步读盘，可能短暂停顿；重置计时，避免将读盘等待传给物理步进或下一个有效帧间隔。资源分发与安装校验仍包含全部资源。

CPU 实测附带原版资源：旧启动 9 个外部网格的 vector 容量共 14,507,076 字节；新启动训练机为 0，A350 为 2,979,315，777 为 6,363,876 字节。这仅计算四个网格数组的 capacity，排除纹理、分配器、渲染器及 GPU；不是进程工作集、启动时间或 FPS。详见 validation_v097/payload.txt。

检查：model_restore_tests.cpp 执行按需缓存、程序生成机型、自定义回退、失败隔离、修复重试；tools/check_on_demand_models.py 抽取真实 main 启动、换机、读档代码块，以 CPU 文件夹和替代 UI 对象执行事务路径。Windows CI 编译真实 main 与 DirectX 代码，仍不执行模拟器或 GPU。

Boot Camp 待验收：DX11 冷启动训练机、A350、777各三次，记录进入主菜单耗时、进程峰值工作集；依次换机、导入、旋转、恢复默认与读档，点检外观和操控；暂移未选机型网格验证启动隔离，再选择该机型验证错误与修复重试。与 v0.96 使用相同资源和设置对比。没有目标机数据，暂不宣称实际性能改善。
