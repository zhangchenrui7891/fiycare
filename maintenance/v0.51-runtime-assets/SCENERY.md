# v0.50 · 机场周边三维地景

在原有浦东离线卫星底图上，为训练机场西侧加入示意住宅、楼房、仓库、农田、相接道路和树带。此版本的重点是让机场周边有三维参照物。

这些是固定种子的程序化示意布局，不是真实浦东建筑轮廓、道路网或精确机场复刻；卫星影像仍为原有 EOX / Copernicus 2016–2017 数据，署名与许可见 CREDITS.md 和 assets/satellite_manifest.json。没有新增地图下载或运行时联网依赖。

## 如何查看

1. 解压完整工程到新文件夹，先运行 `check_release.bat`，再运行 `build_vs.bat`。包内没有游戏 EXE。
2. 在跑道停稳后，打开“设置与视角”，选择“上海浦东 · 卫星图”。默认使用卫星图，但已有存档可能记住山海模式。
3. 起飞后，在训练机场西侧观察新增地景；本地坐标 X 为负的一侧有建筑。可用 C 切换追尾、驾驶舱和俯视视角。W/S 调推力，方向键操纵，F 襟翼，G 起落架。
4. T 切换季节；同一片建筑位置和高度应不变，植被与农田配色随季节变化。

## 范围与实现

- `src/scenery.h` 生成地景，`src/scene.h` 的卫星模式调用它。原有异步地景线程负责生成和发布；没有另加每帧生成任务。
- 布局使用固定的 400 米世界网格、无全局随机状态。保守地限定在机场西侧 X=-4800～-720、Z=-4400～4400 米范围内，并检查整格外沿与两个训练机场及进近走廊的间隔。只在网格中心距当前地景锚点不超过 4200 米时显示。
- 近处（1600 米内）显示窗带、树干与仓库屋顶细节；中距（2800 米内）保留道路、田块和树冠；更远处保留建筑体块。距离按地景网格锚点计算，每移动约 400 米更新，尚无渐隐，细节切换仍可能可见。
- 新增几何每次最多 48000 顶点，按近到远加入完整网格；达到上限不输出半栋建筑。这个上限不包括原有地面、机场、飞机、座舱和 UI，更不是整个程序内存上限。
- 建筑屋顶、墙面和植被提供几何法线供现有光照使用。沿用原来的地面高程、跑道、贴图、物理、存档与画质设置。
- 新增建筑是视觉地景，没有建筑碰撞或障碍物系统。也没有真实 DEM、真实水面/海岸高程、真实路网、密集植被、建筑材质贴图或真实机场布局。

## 检查与证据

`validation_v050` 保存本轮日志与 CPU 投影预览。`scenery_tests.cpp` 检查 192 个相机网格，合计 1925526 个顶点，样本峰值 28644 个新增顶点；原点场景新增 13938 顶点。检查完整三角形、绕序/单位法线、有限数值、地表基础位置、安全区域、固定布局、季节、远近建筑锚点、地面前缀保留及极端索引。这里只能证明这些样例，运行时另外保留 48000 顶点硬上限。

`tools/check_scenery_integration.py` 编译实际 landscape/box/tri 语句，使用恒等 CPU 数学适配，24 组模式/相机/季节用例与冻结 v0.49 对照。原卫星地面顶点和山海模式几何逐字节保持一致，新增几何只出现在卫星模式。该检查没有编译 Windows/DirectX 头文件。

预览 `validation_v050/scenery_cpu_preview.png` 使用导出的真实新增网格与原卫星图，在独立 Python CPU 投影器中绘制。它用于检查布局、朝向和接地，**不是游戏截图**，也没有复现游戏光照、抗锯齿、相机、GPU 或帧率。复现时先用 `scenery_check mesh.txt` 导出，再用 `python tools/preview_scenery.py mesh.txt preview.png`（该可选工具需要 numpy、Pillow）。

本轮 Linux 原生几何、严格 C++17、完整可用目标构建与回归结果见日志；新增测试有 ASan/UBSan 检查（关闭 leak detector）。Windows 检查脚本已加入新几何测试，但本轮没有运行 Windows/MSVC 编译或游戏。

## Windows 实机验收

- 两种地形来回切换后，无跨模式残留；正常卫星图、原机模和座舱均能显示。
- 在机场西侧低空与俯视检查建筑接地、窗带、树带与道路接缝；沿跑道和两个方向的进近路径检查没有新增障碍体块。
- 连续移动跨过地景网格、切换季节，确认建筑不随机改位置；记录可见的 LOD 跳变或加载停顿。
- 对比 v0.49/v0.50 的同机型、同位置、同视角、同时刻和同画质 60 秒帧时及 RAM；现有默认 benchmark 是低负载场景，不能替代默认画质数据。没有目标机数据前，不认定 FPS、RAM 或 HD6000 流畅度改善。

本轮尚无 Windows 游戏启动、真实画面、键鼠、资源复制和 HD6000 性能的新证据。下一步应以实机截图和帧时决定继续增加地景密度还是优化已有几何。
