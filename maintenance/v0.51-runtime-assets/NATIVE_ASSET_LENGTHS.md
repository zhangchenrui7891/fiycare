# v0.49 · 原生资源分配前检查载荷长度

日期：2026-11-01。基线：v0.48文件版本29，ZIP CRC及2053项SHA256核验通过。

## 实际修复

旧loadAtlas/loadModel会先按通过尺寸检查的文件头分配vector，读完后才拒绝截断或尾部多余字节。仅有合法文件头的损坏贴图可请求约64MiB，原生模型可先请求144,000,000字节顶点缓冲，即使文件实际没有载荷。

新增assetPayloadSize：读取已打开流的当前位置和文件末尾，确认剩余字节数严格等于文件头声称的载荷，再回到载荷起点分配和读取。贴图为width×height×4，模型为顶点数×48+三角形数的gear标签字节。尺寸/步长/顶点/标签检查、最终读失败和EOF检查全部保留，原有读取失败及EOF检查均保留。

有效FCTEX005、FCMESH06与FCMESH07格式及最大尺寸/顶点数不变；不降低模型质量、不改气动/存档/画质，不承诺有效大资源占用减少。长度正确但内容损坏的资源仍需读取后执行原有顶点/法线等检查，本修复不是总内存上限。

## 验证

新asset_length_tests.cpp冻结v0.48两个读取函数，仅用于对照。测试拦截超过1MiB的C++ new请求并抛bad_alloc，避免真的分配上述大缓冲；允许不同标准库加入少量分配对齐开销。

- 尺寸字段合法但缺少载荷的文件头：旧读取器确实发出至少67,108,864/144,000,000字节分配请求，被测试拦截；新读取器直接拒绝，针对这些样例没有超过1MiB的C++分配请求。
- 368项截断/尾部附加数据场景拒绝；有效贴图像素及两种原生模型的顶点和标签字节与冻结旧读取器一致，包含中文文件路径。
- 新测试的严格C++17及ASan/UBSan（detect_leaks=0）通过；Linux默认Assimp开启完整Release构建、31/31 CTest、JUnit零失败零跳过、现有真实模型导入回归通过，增量构建无工作。

这些是异常样例与分配请求的故障注入证据，不是进程RSS、GPU显存、HD6000性能、游戏启动速度或FPS实测。测试用的1MiB拦截阈值不会进入游戏程序，也不是有效资源限制。

Windows实际结果以PROGRESS.md及validation_v049最终记录为准；未把工作流触发当作成功。

## 目标机验收

备份玩家文件，check_release.bat、build_vs.bat完成带资源默认构建。确认原有机模、浦东影像及中文菜单正常；在独立测试副本中测试损坏自定义fcmesh被拒绝且保留默认模型，不破坏玩家目录。不要用真实存档做破坏性测试。

随后采默认画质固定机型/机场/时刻60秒帧时、进程RAM及截图。本轮不宣称FPS提高或实际内存峰值下降。

七机型、27控件共用座舱、航电、近似气动、训练NAV/几何进近、双机场任务、生涯、浦东离线底图、FXAA和接管提示保留；原运行资源和第三方文件逐字节相同。完整机型系统/FMS/EFB、精细机场地形、复杂天气、气动实机标定及完整航班仍不足。2026-11-01核对MSFS官方指南：https://www.flightsimulator.com/guide/new-flight-simmer-guide/ ，以物理/航电/天气/生涯为长期参考。没有新增可比较的成品画面或HD6000实机数据，未接近成品，不承诺目标硬件同等画质/功能。
